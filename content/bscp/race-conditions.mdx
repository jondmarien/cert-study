## Checklist

- The gap is check-then-act: the application reads a balance, a coupon, or a single-use token, then writes, and a second request does the same before the write is visible.
- Evidence in a lab is two responses that both claim success, followed by a state that should have allowed only one.
- Burp's Repeater can send a group of requests in parallel in current versions. The note should say when parallel sends are the right observation, and that this is lab-only.
- Defenders use a transaction or a single-use constraint in the database, not a hope that requests arrive slowly.
- Mention the difference between a logic flaw (the rule is wrong) and a race (the rule is right and the window is wrong).
