## Checklist

- The handshake is an HTTP upgrade. After that, frames are not ordinary requests, so CSRF tokens on later HTTP routes do not automatically cover messages.
- The browser sends an `Origin` on the handshake. The server should check it. That is the CORS idea applied to a different channel.
- Each message still needs authorization. A socket opened by a valid user can still ask for another user's object.
- Proxy history shows the handshake. Burp can show the frames in the WebSocket history. The finished note should say which view you use for which half.
- Encryption is `wss` versus a clear socket. That is transport protection, not authorization.
